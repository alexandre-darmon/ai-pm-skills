# AI PM Skills v1.4.0

**Evals as evidence.** The same 29 Agent Skills for AI product managers who build, in regulated European companies. In this release, 13 skills were revised against the critiques of blind judges, then cleaned of everything that only served to please a judge, and every skill is now graded by three blind judges on exactly the text you download.

## What the skills add, by four measures

Same cases, Sonnet 5.5 answering, 3 runs per case; the judges grade the runs recorded for each skill's present text.

| Test | Model alone | With the skill | Gain |
| --- | --- | --- | --- |
| Regex graders, 29 skills | 52% | 97% | +45 |
| Claude Opus 5.5, 29 skills | 70% | 85% | +15 |
| GPT-6.1 Sol, 29 skills | 63% | 72% | +9 |
| Jev 1.14, 29 skills | 80% | 90% | +10 |
| Red lines held | 71% | 100% | |

- The regex graders check that an answer contains what the skill asks for; the skills' author wrote them, so they favour the skill.
- The judges grade general quality without knowing which answers used the skill. GPT-6.1 Sol (OpenAI) and Jev (TypeSafe) come from other vendors and agree on about +9 to +10 points. Claude Opus 5.5 sees more (+15); it is from the same family as the model that writes the answers, so part of that gap may be self-preference.
- None of the judges checks legal correctness. On `ai-act-classification`, GPT-6.1 Sol scores the answers with the skill lower (−6) because it marks down the 2026 AI Act amendments (Regulation (EU) 2026/1744: Annex III high-risk from 2 December 2027), which are correct and which the skill keeps. Counsel's review remains the evidence for the six legal skills.

Per skill, the README chart shows the regex gain next to the three judges' gains; their larger disagreements stay visible.

## What changed in the skills

Thirteen skills where GPT-6.1 Sol first saw +5 points or less were iterated on its critiques. An independent review of those edits then found and removed what had crept in to raise the score: wording and expected answers copied from the eval cases, red lines dropped from "Rules and red lines", correct law removed because the judge did not know it, and statistics without their assumptions. Each skill was rerun after the fixes (3 runs per case, every red line held).

Skills revised: `ai-act-classification`, `ai-vendor-evaluation`, `model-card-ai-registry`, `ai-incident-playbook`, `production-evals-monitoring`, `process-ai-redesign`, `conversation-analysis`, `release-to-production`, `agent-design-and-tooling`, `agent-evals`, `llm-judge-calibration`, `model-selection`, `prototype-handover`.

Examples of what the answers now do better:

- **`ai-act-classification`**: a memo proportionate to the risk (about a page below high risk); the use sets the Annex III category at every autonomy level; emotion recognition means inference from biometric data; dates as last checked, never an invented "today".
- **`model-selection`**: a gap within the noise never justifies the costlier model; a thin margin over the threshold is flagged as a risk with the arithmetic shown, not turned into a new gate.
- **`agent-design-and-tooling`**: data scope comes from the trusted session or case, never from model output; a missing cap gets one proposed value marked as an assumption for its owner.
- **`conversation-analysis`**: lead with the confidence-routed setup rather than one model alone; no taxonomy work on unmasked text.

## Output templates that changed shape

If you parse or reuse these outputs, check them:

- `ai-act-classification`: the level-change table has five columns (action; today → after; Annex III point or why outside; duties at both levels with the date each applies from; what the move changes). New section "Risks outside the AI Act". Evidence status "not seen" replaces "missing".
- `ai-vendor-evaluation`: the document table gains "Applies if"; status values add "requested".
- `ai-incident-playbook`: the detection-sources, rollback-owner and evidence-loop headings carry more fields.
- `model-selection`: the decision record states the gap, how sure it is, and the price of the gap only when a costlier model scores higher.
- `prototype-handover`: handover-file fields reworded.

## Tooling

- Judges from three sources in one script: Claude models on the subscription (`--model claude-opus-5-5`), OpenRouter models (`--model openai/gpt-6.1-sol`, `typesafe/jev-1.14`), and local models through Ollama (`--model ollama/<name>`, one call at a time to keep memory out of swap).
- Each judge file records which run of the skill it graded; the README says "current runs" only when that matches.
- Graders that rejected correct answers were fixed in three skills; each correct answer is now a fixture.
