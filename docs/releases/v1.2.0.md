# AI PM Skills v1.2.0

**Evals as evidence.** The same 29 Agent Skills for AI product managers who build, in regulated European companies, now graded by judges from other vendors too. Every skill in this release has a recorded eval run on exactly the text you download, and passes it.

## New in v1.2.0

### Judges from other vendors

Claude writes the eval answers, so a Claude judge may favour them. This release adds two judges that are not Claude, through OpenRouter, on the recorded runs of the 23 non-legal skills (498 answers, each graded twice, blind to the arm):

| Same answers | Model alone | With the skill | Gain [95% interval] |
| --- | --- | --- | --- |
| GPT-6.1 Sol (OpenAI), general LLM on the Claude judges' rubric | 63% | 72% | **+9 points [+6, +12]** |
| Jev 1.14 (TypeSafe), decision model, one score per criterion | 81% | 90% | **+9 points [+7, +11]** |
| Regex graders | 53% | 95% | +42 points |

Two vendors and two methods agree with the earlier Claude judges (about +10): the skills improve the answers, and the gain is not Claude grading Claude. They also show the size of it: about +9 points of general quality, against +45 on the regex graders, which check the specific items each skill asks for. Legal skills are never judged.

To run it yourself: `python3 scripts/judge_answers.py --recorded --model <vendor>/<model> skills/*`, with an OpenRouter key in `OPENROUTER_API_KEY` or a git-ignored `.env`. Details: [docs/evaluation.md](../evaluation.md).

### Four skills improved from the judges' critiques

On four skills both outside judges saw no gain: the answers contained what the skill asks for, but a demanding reader found them no better. GPT-6.1 Sol's written critiques pointed at causes in the skills, now fixed as general rules:

- **`model-selection`** (0.3.0): overlapping confidence intervals no longer read as a tie. Without the count of cases where only one model is right, the answer asks for it and says the gap is not shown to be real; the cheaper model wins as a decision under uncertainty, said as such.
- **`agent-design-and-tooling`** (0.4.0): data access is scoped by the trusted session or case, never by an ID the model extracted; a cap or limit the brief does not give gets one concrete proposed value marked as an assumption for its owner; text sent to a customer is checked against the tools' facts; ordered steps or least privilege are not reasons for multi-agent.
- **`system-prompt-and-guardrails`** (0.3.0): figures and policies the brief does not give become assumptions with an owner; a re-test never shrinks the attack set, keeps a held-out part and fixes pass criteria before the run; the higher autonomy level stays blocked until the guardrail tests pass.
- **`llm-judge-calibration`** (0.2.0): no default target presented as given; the answer computes which term (TPR, TNR or the sample) drives the corrected rate's uncertainty; review effort goes to the costly error.

Each was rerun on Claude (3 runs per case, pass, red lines held) and re-judged. Gain from the skill, points:

| Skill | GPT-6.1 Sol, before → after | Jev, before → after | Sonnet 5.5, after |
| --- | --- | --- | --- |
| `system-prompt-and-guardrails` | −4 → +7 | +1 → +1 | +12 |
| `llm-judge-calibration` | 0 → +4 | 0 → +3 | +6 |
| `agent-design-and-tooling` | 0 → +4 | −1 → −5 | +6 |
| `model-selection` | −1 → +2 | −1 → +2 | +4 |

Nine answers per arm per skill: these gains are small and partly within the judges' noise. Jev, which gives no reasons, still sees no gain on `agent-design-and-tooling`.

### Also changed

- README table: one number per gain column; the intervals stay in [skill-eval-gains.md](../../skill-eval-gains.md).
- `agent-design-and-tooling` case 001: a grader that rejected a correct answer ("`not_found` and `erp_error` are different results") is fixed; the skill was rerun with both arms.

## The evidence

Same cases, Sonnet 5.5 answering, 3 runs per case: regex graders 52% alone, 96% with the skill, **+45 points [+41, +48]**; red lines held 100% with the skill; 172 of 174 routing runs correct with all 29 skills installed (no description changed in this release). Per-skill numbers: [skill-eval-gains.md](../../skill-eval-gains.md).
